# Current capability status

This audit records what the current application can do, which paths still need
work, and where each conclusion comes from.

It reflects commit `ae2fc1d`. A **user entry point** is a control or page a
person can reach in the current browser interface; the existence of a Flask
route alone does not make a capability user-facing.

Every row was re-checked against `ae2fc1d` in this pass. That means each cited
file was confirmed to exist at the path given, and each **user entry point** was
confirmed against the live step list in `static/app/core/state.js` and the stage
module that renders it.

It does not mean every sentence in the *Known limitation* column was re-tested.
Those are the claims most likely to age, and a reader relying on one should
check it against the cited source.

![The five capability labels arranged by whether a user interface and a backend implementation exist](../assets/diagrams/p-status-labels.svg)

*Supported, experimental, backend-only, blocked, and historical, and what separates them.*

## Status labels

- `supported`: wired through a current user interface to its backend
  implementation.
- `experimental`: user-facing, but dependent on optional or external systems,
  or not yet covered well enough to treat as a dependable primary path.
- `backend-only`: implemented behind routes or pipeline functions but absent
  from the registered browser workflow.
- `blocked`: an interface advertises the capability, but the current wiring
  cannot complete it.
- `historical`: retained only as earlier behavior or reference material.

## README statements repaired

The previous audit recorded four stale claims in the two READMEs: that the
marker flow was wired into the interface, that marker assignment failed for
